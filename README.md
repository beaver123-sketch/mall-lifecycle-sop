# 商城数据分析与生命周期管理

**[打开商城数据中心](https://beaver123-sketch.github.io/mall-lifecycle-sop/)** · **[管理员身份验证](https://beaver123-sketch.github.io/mall-lifecycle-sop/cloud-admin.html)**

## 使用流程（2026-11-04 云端共享版）

**方案 A：知道网址的人可以免登录查看已发布的月度经营分析；只有云端授权管理员能上传、修改和删除订单文件。**

### 管理员第一次使用（重要）

1. 在**原来上传数据的电脑、同一个浏览器**打开「数据管理」：https://beaver123-sketch.github.io/mall-lifecycle-sop/#data
2. 如果显示「本地历史数据尚未同步」，点击 **一键同步本地历史数据**。历史月份的解析订单数据及仍保留在浏览器中的 Excel/CSV 原文件会被上传到 Supabase 的私有库；已发布月份不会被覆盖。
3. 等同步成功，再让其他同事刷新网页。云端未迁移的月份仍不会对外可见。
4. 之后在网页上传新的 Excel/CSV、删除文件或修改新品 ID，操作会更新云端存档与公开月度分析。删除只影响当前平台、当前月份。
5. 在「云端管理员」完成邮箱登录与授权后，主网页使用同一浏览器的登录会话。不是管理员的人只可查看三项月度分析。

### 普通同事查看

无需登录。打开相同网址，即可查看**经营总览、新品分析、设计方向**，选择历史月份追溯。平台选择和月份选择同步生效，刷新页面会保留选择；新设备默认展示最新已发布月份。

**动态上下架季度明细目前仍为管理员专用**，尚未同步成公共季度报表。请勿将季度本地结果当作已共享。原功能在管理员端保留，逻辑未删除。


## 设计方向（新增：整套主题与独立座驾）

「设计方向」页新增设计提需推荐。**一套主题装扮 = 头像框 + 资料卡 + 派对背景 + 聊天气泡**，四个品类统一设计名称、色系和核心关键词，各自有独立执行说明；**座驾单独作为独立设计提需**，包含外观与登场动效。

- 选择「主题装扮套装」时，推荐数量按**套**计算；例如 4 套 = 4 个统一主题、16 条品类执行说明。
- 选择「座驾」时，推荐数量按**款**计算，不与主题套装混排。
- 每条推荐包含：明确设计名称、5 个关键词、统一配色、创意构想、品类设计说明、动效参考、相关历史销售依据。
- 「商品设计标签管理」仅管理员可编辑。通过平台 + 品类 + 商品 ID 绑定主题材、视觉风格和元素，所有查看者可见题材销售分析。
- 销售依据仅来自真实已发布月报及已保存商品标签，默认参考最近 3 个已发布月份；尚无标签或相关样本时明确标记「创意候选」，不将示例方案称为经过数据验证的爆款。
- 导出设计提需 CSV：每套主题拆成 4 行对应四个装扮品类，座驾每款 1 行。
- 原有「新品系列表现」「品类设计参考」保留不变；原销售数据、动态上下架和管理员权限保持原有逻辑。

## 数据口径

- SKU 唯一键：平台 + 品类 + 商品 ID，重号跨品类不合并。
- 1 美元 = 1000 金币；荣誉券单独统计，不与金币收入合计。
- 混合支付可能让金币销量和荣誉券销量重叠，总销量以订单源文件的总销量字段为准。
- 同日 + 品类 + ID + 购买期限相同值去重；冲突值不计入总销量。
- 不把订单表中没有出现的商品直接判断为零销量。
- 季度动态上下架以原 SOP 完整评估为准，不能仅依据公开月报推断下架候选。

## 云端权限与数据存储

- 托管网页：GitHub Pages；数据服务：Supabase 项目 **Mall Data Center**（Singapore）。
- 公开数据库 `mall_month_reports`：按月收入、销量、SKU 统计、每日曲线、各品类汇总、上新指标等**派生分析数据**；不包含 Excel 原文件或完整解析订单档案。
- 私有数据库 `mall_private_month_archives`：完整解析订单数据和商品文件清单，只允许授权管理员读写。
- 私有对象存储 `mall-order-source`：管理员上传的 Excel/CSV 原件。历史浏览器里若无原件，只能同步已解析数据。
- 权限由 Supabase RLS 在服务器端执行：匿名用户仅读取公开报表，不能获取私有档案，不能上传、删除或修改。
- 原浏览器 IndexedDB `mall-month-archive-v3` 仍作为旧系统兼容缓存与本机历史备份，**但它不再是共享看板的统计数据源**。
- **安全边界：** 知道网址的任何人都能查看公开的销售汇总数据，不能将方案 A 当作严格的公司内网权限控制。
