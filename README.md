# 商城动态下架管理系统 · V1.2

基于2026年4—6月原商城下架分析HTML升级，**保留196条历史SKU明细、品类阈值、原审核与本地记录**，采用白色管理台布局，优先展示最新数据上传及动态下架候选名单。

**访问：** https://beaver123-sketch.github.io/mall-lifecycle-sop/

## 最新数据使用说明

1. 打开网页上方「商城动态下架分析」，一次选择一批商城导出 Excel（.xlsx/.xls）或 CSV，可多文件导入；不需要在 GitHub 手动上传销售数据。
2. 选择本批次平台（POPPO / VONE），确认分析开始/结束日期；系统默认优先使用最新90天。未结束的当天数据默认排除，可以手动调整。
3. 自动识别常见商城导出字段：日期、商品类型、商品名称（从括号提取商品ID）、购买天数、总销量、金币/荣誉券支付销量及对应金额等。派对主题与派对背景统一为一个分析品类。
4. 自动识别同日期+平台+品类+SKU+购买天数的**疑似重复/冲突**，临时排除重复记录并标注原始文件及行号。区间无记录的日期只提示核对，**不自动断定数据缺失**。
5. 输出商品级候选：**优先复核、持续观察、低贡献观察、样本观察**。显示具体商品名称、ID、销量、近30天销量、分别计算的金币/荣誉券贡献及入选理由。
6. 运营可选择「保留、持续观察、拟下架、已执行下架」等人工审核状态，导出下架候选CSV和异常CSV。审核选择保存在当前浏览器；导出CSV才能形成可共享记录。

**边界**：数据处理在浏览器内完成，上传的销售文件不会自动发送到 GitHub 或服务器。Excel解析通过外部SheetJS CDN加载，网络不可用时可改上传 UTF-8 CSV。浏览器刷新后需要重新选择源数据文件。

## 分析规则与限制

- 原报告的金币贡献阈值（头像框0.2%、派对背景0.2%、资料卡0.5%、座驾0.5%、聊天气泡0.3%）只用于初筛，不直接判定下架。
- 按单个平台、单个品类分母分别计算金币和荣誉券贡献率，**不把两种货币金额相加**。
- 满90天的样本，销量0—1件优先复核；2—5件进入持续观察；还可结合双渠道低贡献、最近30天销量及连续下滑判断。**不足90天仅输出阶段性观察**。
- 仅凭订单数据无法发现「没有销售记录的零销量SKU」，也不能确定商品上架日期、完整在售天数、活动/季节属性。执行下架前必须获取在售SKU清单并人工核验。
- 日期无记录≠必然漏单。重复、同维度冲突、支付字段缺失与短周期都会产生醒目的数据质量限制；任何候选**不等于系统已下架**。
- 2026年4—6月历史报告的442 SKU总体统计与196条明细仍原样保留为历史快照，不参与新数据自动汇总。

## 发布与迭代

- 页面源代码：仓库根目录 `index.html`；完整规则说明：`SOP.md`。
- GitHub `Settings → Pages → Build and deployment → Source` 选择 `GitHub Actions`。
- 向 `main` 提交代码后，仓库内的 `.github/workflows/deploy-pages.yml` 将自动部署；刷新网站查看最新页面。**不使用 Vercel**。
- 页面上传与分析无需提交 GitHub，且不会把内部交易数据公开写入静态代码仓库。共享分析结果请从页面导出CSV。
