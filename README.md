# 商城数据分析与生命周期管理

**[打开商城数据中心](https://beaver123-sketch.github.io/mall-lifecycle-sop/)** · **[进入原动态上下架后台](https://beaver123-sketch.github.io/mall-lifecycle-sop/lifecycle.html)**

项目继续使用原仓库与 GitHub Pages。经营总览、新品分析、设计方向、数据管理构成统一的清爽白底首页；原有动态上下架 V2.2 页面保存在 `lifecycle.html`，算法和历史功能未删除。

## 使用流程

1. 进入「数据管理」或点击右上角「上传数据」，选择商城订单 Excel / CSV；可以一次上传多个文件，按订单日期自动归档到月份。
2. 选择年份和月份，经营总览自动展示总销量、金币收益、荣誉券、成交 SKU、日销售折线和品类排行。
3. 在「数据管理 → 本月上新商品 ID」登记本月上新商品。2026 年 10 月内置了当月的 20 个新品 ID；可以修改保存。新老品对比与系列分析随订单数据自动更新。
4. 在「新品分析」查看销量、金币与荣誉券、首销后日均和趋势；在「设计方向」查看同名跨品类系列表现。
5. 进入「动态上下架」查看原季度评估、下架候选、已下架台账和备份。月度上新 ID 在上传/保存后会同步给旧季度系统。

## 关键数据口径

- 商品唯一键：平台 + 商品品类 + 商品 ID；同名不同商品或跨品类重号不合并。
- 全站经营总览包括五类装扮、推荐套餐、靓号；原下架评估仅覆盖五类既定装扮。
- 金币收益换算为美元：1000 金币 = 1 美元；荣誉券单独统计，不与金币收益金额相加。
- 金币销量、荣誉券销量可能因混合支付重叠，经营总销量采用原始「总销量」字段。
- 同日期 + 品类 + ID + 购买期限的完全相同记录去重；不同统计值冲突的同键记录隔离并提示。
- 商品当月首销日不等于实际上架日期，后续若能取得实际上架日期，可进一步分析上线后第 7/14/30 日表现。
- 仅凭订单统计不能识别所有在售但零销售的 SKU；季度正式下架名单须按原 SOP 完整校验。

## 存储与部署

订单文件和解析记录保存在浏览器 IndexedDB；新品及管理配置在 localStorage。**数据不会因为使用 GitHub Pages 而上传到 GitHub**。不同设备之间不自动同步；在「数据管理」使用「导出备份 / 恢复备份」迁移解析后的数据。原浏览器数据仓库 `mall-month-archive-v3` 与原动态上下架页共用。

部署仍由 `.github/workflows/deploy-pages.yml` 自动完成。JS 基础语法由 `.github/workflows/validate-dashboard.yml` 校验。

原始下架逻辑详情参见 [SOP.md](SOP.md)。
