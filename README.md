# 商城动态下架管理系统 — SOP V1.1

此仓库基于《商城下架商品分析 · 2026年4—6月》原始HTML升级。原始品类表格、历史金额、阈值及勾选结构均保留；新增可执行的下架SOP、数据质量门禁、历史风险提示、人工审核、备注与本地备份。

## 使用及部署

- 使用 GitHub Pages 静态部署，无需 Vercel。仓库根目录 `index.html` 即入口。
- 在仓库 Settings → Pages → Build and deployment 选择 `Deploy from a branch`，分支 `main`、路径 `/(root)`。
- 以后修改 `index.html` 提交到 `main`，等待 GitHub Pages 发布后刷新网页；如浏览器缓存旧版，可强制刷新。
- 审核结果目前只保存在**当前浏览器 localStorage**，不自动提交到 GitHub。操作后请定期点击「备份审核JSON」，在其他设备可用「恢复审核JSON」导入。
- 导出审核CSV用于运营核查。尚未接入真实Excel导入、自动数据核验、动态近90天指标与真实下架接口。

## 数据限制

- 2026年4—6月历史报告统计442个SKU，但页面只提供196条明细，座驾仅3条（原报告称该类有6条命中历史阈值），靓号47条不显示。
- 原版的排名是按**品类金币销售额贡献升序**，并非按销量升序。原版金币下架阈值现仅用于历史预警，不生成自动下架结论。
- POPPO与VONE历史数据合并；没有原始每日交易记录、商品在售时间和支付方式明细的完整验证信息。
- 人工勾选门禁不等于自动完成数据质量验证；历史样本不支持直接下架执行。

## 迭代顺序

1. V1.1：SOP + 历史基线 + 审核记录 + CSV/JSON备份（当前版本）。
2. V1.2：导入/映射CSV、Excel，生成源文件清单；去重、漏期、合计对账并锁定异常批次。
3. V1.3：全量SKU归并，按平台和品类计算滚动90/30天、双支付渠道贡献、风险分层、前后期趋势。
4. V1.4：人工审核结果和数据版本的仓库持久化（须用安全身份鉴权或提交审核PR，不在客户端内置密钥）。

详细规则见 [SOP.md](./SOP.md)。
