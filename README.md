# 商城商品动态上下架管理 · V2.2

[打开 GitHub Pages 后台](https://beaver123-sketch.github.io/mall-lifecycle-sop/)

## 核心使用方式

**每年建立12个月的数据仓库，按月上传，按季度自动计算。** 每次上传不用重新制定规则。

1. 选择年份、平台及月份，将本月的商城订单Excel/CSV上传到对应月份。一个月支持多个文件；同名文件替换，其他文件不受影响。
2. 月度数据保存在**当前浏览器的IndexedDB**，刷新页面仍可复用；上传同一季度的3个月文件，系统即可分析该季度。
3. 在“本季度上新商品ID”展开输入对应品类的上新ID。系统保存平台+季度记录，并排除本季度和上季度登记的上新商品。
4. 查看“季度汇总”“建议下架商品”“持续观察商品”，导出下架名单CSV。某个月文件解析失败时，展开该月「文件解析情况」定位原始文件和行号；可点击「重新解析已存文件」，缺少品类列时可在文件旁选择品类后重试。
5. 在商城后台实际下架后，直接在「建议下架商品」的对应行勾选「已下架」，系统自动写入ID、名称、品类、勾选日期和来源季度；已下架记录可撤销，后续自动排除重复推荐。
6. 使用“备份本年度数据（JSON）”保存当年的月度解析记录、上新ID、已下架记录及季度分析摘要；可以恢复到当前/其他浏览器。

**隐私和存储**：商城订单文件只在浏览器中解析并存储，不上传到公开 GitHub 仓库。年度备份包含业务数据，请妥善保存；更换设备、无痕模式或清空网站数据会影响本地保存。备份JSON保存的是解析后的数据，恢复后可继续分析，但需重新上传源文件才能直接取回原始Excel。

## 既定下架公式

| 品类 | 每月上新 | 季度上新 | 季度下架上限 |
|---|---:|---:|---:|
| 头像框 | 4 | 12 | 8 |
| 派对背景 | 4 | 12 | 10 |
| 资料卡 | 4 | 12 | 5 |
| 聊天气泡 | 4 | 12 | 4 |
| 座驾 | 1 | 3 | 1 |
| 合计 | 17 | 51 | 28 |

- 每个季度按**平台 + 品类 + 商品ID**汇总订单，合并15天/30天等购买期限。
- 分别计算季度销量和成交活跃度（有成交天数/完整季度天数），取同品类两组排名的后25%，取交集。
- **并列规则**：如果同一数值的多个商品横跨25%截止位置，不强制按ID任意截取该组并列商品，以免误判。
- 需求回升排除：近30天销量≥5，且比前60天月均销量增长≥20%（前60天为0时按近30天≥5判断）。
- 剩余商品按成交天数从少到多、季度销量从少到多、ID顺序排序。各品类分别按季度上限截取，不强制下满。
- 当前订单数据视作**有成交记录的在售商品范围**；订单未覆盖的零销量在售商品无法识别，不应当成全部在售SKU清单。
- 本季度和上一季度登记的新品排除，已下架商品自动排除。没有上新登记时会提示风险，不伪造上架日期。
- 季度订单缺月、季度尚未结束或存在关键字段冲突时不生成正式下架名单；订单无记录日可能是正常零成交，并非必然漏导。
- POPPO与VONE分别分析；金币和荣誉券件数均纳入总销量，不将不同币种金额直接相加。
