# 商城商品动态上下架管理 V2.0

**访问地址：** https://beaver123-sketch.github.io/mall-lifecycle-sop/

每季度上传商品订单，系统自动识别字段、去重与定位冲突、计算成交活跃度、同品类季度销量排名，按固定规则生成季度下架名单。GitHub Pages 静态部署，不使用 Vercel。

## 使用流程

1. 首次导入商品基础清单（CSV、XLS、XLSX），字段至少包括：`商品名称`、`商品类型`、`上架日期`、`在售状态`，以及可提取的商品ID（独立列`商品ID`或商品名称后缀`（1234）`）。以后的季度复用本浏览器清单，仅更新有变化的商品。
2. 每季度导入完整自然季度的订单统计（可多文件），系统自动检测`日期`、`商品类型`、`商品名称`、`总销量`、`金币销量`、`荣誉券销量`等字段。
3. 选择POPPO/VONE和季度，系统自动完成数据质量检查、商品汇总、排序和配额。
4. 查看品类汇总、具体SKU下架清单和观察清单，下载建议下架CSV。下架在商城原后台手动操作，本网站不自动调用原后台。
5. 分析结构校验通过后，季度结果摘要自动保存在当前浏览器。

**重要：** 所上传文件只在用户浏览器本地解析，销售数据不会自动提交到公开GitHub仓库。浏览器清理存储或更换设备后，本地商品清单和历史分析结果可能不可用；请下载基础清单备份及季度CSV存档。

## 固定计算规则

- 在售商品资格：商品已上架满180天，当前在售且非活动/权益/靓号等特殊商品。
- 按`平台 + 品类 + 商品ID`归并，不同购买期限合并为一个商品；金币与荣誉券购买件数均计入总销量。
- 同品类按季度销量升序排名，取后25%；按`成交天数 / 有效可售天数`升序排名，取后25%。两个集合的交集作为低效候选。
- 最近30天销量≥5件，并比前60天月均增长≥20%（前60天为0时，最近30天≥5件），判定回升并排除。
- 其余候选按照成交天数升序、季度销量升序、商品ID顺序排序，按品类上限截取，不强制补满。
- CSV中未出现的零销量SKU必须从基础清单补足；仅订单数据不能判断真实上架时间。
- 商品基础清单的当前在售状态不一定能证明历史整季度连续在售，若商品曾暂停售卖，应补充准确的有效可售天数；当前简单版本默认当期常规商品持续可售。
- 无成交日期只是缺失线索，不等于确认漏导；当源文件支付拆分错误、关键字段异常或同维度冲突时，系统停止正式推荐。
- 目前不自动验证后台跨页漏导，需确保导出来源完整。前一季度已完成手动下架的商品，应更新基础清单中的在售状态，以免下一季度重复纳入。

完整规则见 [SOP.md](./SOP.md)。

## 文件结构

- `index.html`：后台页面和2026年4—6月历史参考报表。
- `assets/v2.css`：白色UI样式。
- `assets/v2.js`：导入、校验、固定下架规则、结果导出与本地存档。
- `.github/workflows/deploy-pages.yml`：主分支更新后发布 GitHub Pages。

部署：仓库的 Settings → Pages → Source 选择 GitHub Actions。代码提交到 `main` 后会自动发布，刷新网页即可查看新版。
